# 교실 알람 확장 설계 — 시간표 / 아침활동 안내판 / 알림장 / 위젯화 / 하이클래스 연동

- 작성일: 2026-09-08
- 대상 저장소: imzerguser-cpu/alarm (로컬: `D:\alarm`)
- 대상 사용자: 초등학교 3학년 담임 교사 1인, 학생 5명, 교실 전자칠판(태블릿) 1대 + 교사 개인 폰/PC

## 1. 배경

기존 `index.html` + `js/bell.js`는 시각+메시지 목록을 localStorage에 저장하고 정해진 시각에 음성(TTS)과 배너로 알려주는 "수업종 알리미"다. 프레임워크·백엔드 없는 순수 HTML/CSS/JS이며 GitHub Pages로 공개 배포되어 있다.

이번 작업은 이 기존 알리미는 그대로 두고, 같은 화면에 다음 기능을 추가한다.

1. 오늘 요일의 교시별 시간표 (오른쪽, 세로)
2. 아침활동 안내판 (가운데, 시간 지나면 자동으로 사라짐) + 프리셋/직접입력 카운트다운 타이머
3. 알림장 (가운데, 교사 안내문 + 학생 5명의 할일/1인1역, 하이클래스용 복사 버튼)
4. 태블릿 홈 화면에 앱처럼 설치(PWA)
5. PC(데스크톱 브라우저)에서 항상 위에 떠 있는 플로팅 미니 위젯(Document Picture-in-Picture, 선택 기능)

추가로 시간표/아침활동/알림장 내용을 교사의 폰·PC에서도 입력할 수 있어야 해서, 기존 localStorage 단독 저장 방식을 Firebase Firestore 공유 저장소로 바꾼다.

하이클래스(가정통신 앱) 자동 연동은 조사 결과 공식 API가 없고, 완전 자동화(로그인 자동화)는 브라우저 동일 출처 정책상 웹앱만으로는 불가능하며 별도 프로그램·서버·계정정보 저장이 필요해 리스크가 크다. 따라서 이번 스펙에서는 **반자동(알림장 내용을 정리해 클립보드로 복사 → 교사가 하이클래스에 직접 붙여넣기)** 만 구현한다. 완전 자동화는 범위에서 제외한다.

## 4. 기능 상세

### 4.1 상단 시계·날짜
기존 `clockNow`/`clockDate` 로직을 재사용하되, 화면 최상단 중앙에 크게 배치한다. 형식: `2026년 9월 8일 화요일` + `HH:MM:SS`.

### 4.2 시간표 (오른쪽, 세로)
- 오늘 요일에 해당하는 교시 목록을 세로로 나열 (시간 + 과목명).
- 현재 진행 중인 교시는 배경색 등으로 강조.
- 화요일이 아니면 6~8교시 자리에 "방과후수업1/2/3" 라벨과 해당 프로그램명을 보여준다.
- 편집모드(PIN 필요)에서 교시별 과목을 수정 가능: 프리셋 드롭다운(국어/수학/사회/과학/영어/도덕/실과/음악/미술/체육/창체/방과후/기타) + "기타" 선택 시 직접 입력.
- 요일별 전체 시간표를 편집할 수 있어야 하며(월~금 전부), 화면에는 오늘 요일분만 보여준다.

### 4.3 아침활동 안내판
- 가운데 상단에 교사가 입력한 텍스트 표시.
- 09:00(1교시 시작)이 되면 자동으로 화면에서 사라짐 — 클라이언트 시계 기준으로 매초 체크.
- 편집모드에서 텍스트 입력/수정.
- **타이머**: 아침활동 중 타이머를 쓰는 활동이 있어 안내판 안에 카운트다운 타이머를 둔다.
  - 프리셋 버튼: 1분/3분/5분/10분 — 클릭 즉시 해당 시간으로 설정.
  - 직접 입력: 분 단위 숫자를 입력해 원하는 시간으로 설정 가능.
  - 시작/일시정지/초기화 버튼, 큰 글씨의 남은 시간(분:초) 표시.
  - 종료 시 기존 음성 안내(Web Speech API)로 "타이머가 끝났습니다"를 읽어주고 화면에도 강조 표시.
  - 아침활동 시간대에만 쓰는 건 아니고 언제든 켤 수 있는 상시 위젯으로 둔다(용도를 아침활동으로 제한하지 않음).
  - 기기별 로컬 상태로만 동작(Firestore에 저장하지 않음) — 실제로 타이머를 트는 기기는 한 번에 하나(교실 화면)이므로 기기 간 동기화가 필요 없다는 판단.

### 4.4 알림장
- 상단: 교사가 입력한 오늘의 전체 안내문(자유 텍스트).
- 알림장 영역 왼쪽에 학생 5명을 세로로 나열. 학생별로 이름 옆/아래에 해야할일·제출할 것 등을 적을 수 있는 텍스트 공간을 하나씩 둔다.
  - 지금 단계에서는 이 공간을 단순 자유 텍스트 입력칸으로만 구현한다(체크박스, 태그 등 세부 기능은 넣지 않음). 실제 사용해보고 필요한 세부 기능은 추후 별도로 요청받아 추가한다.
  - 1인1역은 이 텍스트 공간과 별도로 표시(자주 안 바뀌는 정보이므로 구분).
- 학생 명단(번호+이름) 및 1인1역은 엑셀 업로드(xlsx, 번호·이름 두 열)로 일괄 등록/수정 가능 — 클라이언트에서 SheetJS로 파싱, 서버 업로드 없음.
- 5명 고정이므로 칸 크기는 알림장 영역에 맞춰 자동 분배(스크롤 없이 한 화면에 모두 표시).
- 편집모드에서 안내문·학생별 할일·1인1역 인라인 수정.

### 4.5 하이클래스 연동 (반자동)
- 알림장 영역에 "하이클래스용 복사" 버튼 상시 표시.
- 클릭 시 오늘 안내문 + 학생별 할일을 보기 좋은 텍스트로 조합해 클립보드에 복사(Clipboard API).
- 교사가 하이클래스 사이트에 직접 붙여넣기.
- 완전 자동화(로그인 자동 게시)는 범위 밖. 필요해지면 별도 프로젝트(PC/서버 스케줄러)로 추후 검토.

### 4.6 위젯화 (PWA)
- `manifest.json` + service worker 추가 → 설치 가능한 웹앱으로 전환.
- "홈 화면에 추가" 버튼: `beforeinstallprompt` 이벤트를 지원하는 브라우저(안드로이드/크롬 계열)는 설치 팝업을 바로 띄움. 미지원 브라우저(iOS Safari 등)는 "공유 → 홈 화면에 추가" 수동 안내 문구를 표시.
- 설치 후에는 일반 앱처럼 열고 닫을 수 있음 (화면을 통째로 잠그는 키오스크 모드는 사용하지 않음 — 수업 중 다른 화면으로 전환할 수 있어야 하기 때문).

### 4.8 PC 플로팅 위젯 (선택, 데스크톱 전용)
- 태블릿(전자칠판)에서는 다른 앱 위에 항상 떠 있는 진짜 오버레이가 불가능하다(4.6과 동일한 이유 — 안드로이드 오버레이 권한은 네이티브 앱만 요청 가능). 대신 교사 PC에서는 **Document Picture-in-Picture API**(크롬/엣지 데스크톱 최신 버전)로 유사한 효과를 낼 수 있다.
- "PC 플로팅 위젯 열기" 버튼 클릭 시, 작은 창(시계, 오늘의 현재 교시·과목, 아침활동 타이머)이 다른 프로그램(수업자료 PPT 등) 위에 항상 떠 있는 형태로 열린다.
- 지원하지 않는 브라우저(파이어폭스, 사파리, 구형 크롬 등)에서는 버튼을 비활성화하고 안내 문구를 표시한다.
- 이 창은 메인 화면과 같은 Firestore 데이터를 그대로 구독하므로 별도 동기화 작업이 필요 없다 — 태블릿 화면과 PC 플로팅 창은 항상 같은 내용을 보여준다.

### 4.9 편집 보호 (PIN)
- 화면의 "편집" 버튼 → 4자리 PIN 입력 → 일치하면 편집모드 진입(시간표/아침활동/알림장/학생정보 모두 인라인 편집 가능해짐).
- PIN은 캐주얼한 보호 수준이며 강력한 보안은 아님(학생 이름 수준의 낮은 민감도 데이터라는 전제). 더 강한 보호가 필요하면 추후 Firebase Auth 도입 검토.

## 5. 데이터 모델 (Firebase Firestore)

기존 계정을 그대로 사용. 컬렉션/문서 구조:

- `schedule/weekly` — 요일별(mon~fri) 교시별 과목 매핑 (정규 시간표 + 방과후 라벨)
- `roster/students` — 학생 5명의 {번호, 이름, 1인1역} 배열
- `daily/current` — { date, morningNotice, generalNotice, todos: { 학생번호: 할일 } }
  - 날짜가 바뀌면(클라이언트에서 감지) `morningNotice`, `generalNotice`, `todos`는 빈 값으로 초기화. `roster`는 유지.
- 태블릿/폰/PC 모두 `onSnapshot`으로 실시간 구독 → 한 기기에서 편집하면 다른 기기 화면에 즉시 반영.

## 7. 기술 스택

- 순수 HTML/CSS/JS (프레임워크 없음, 기존 방식 유지)
- Firebase Firestore (실시간 동기화), Firebase Hosting은 사용하지 않고 기존 GitHub Pages 유지
- SheetJS(CDN) — 엑셀 학생 명단 파싱
- Web Speech API — 기존 음성 안내 그대로 사용
- PWA: `manifest.json` + service worker (오프라인 캐싱은 최소한으로, 핵심은 설치 가능 여부)

## 8. 에러 처리

- Firebase 연결 실패/오프라인: 마지막으로 수신한 데이터를 화면에 유지하고 "연결 끊김" 표시. 재연결되면 자동으로 최신화.
- 오늘 날짜의 `daily` 문서가 아직 없는 경우(학기 초 등): 빈 템플릿(안내문 없음, 할일 없음)으로 표시.
- 엑셀 업로드 형식이 예상과 다르면(열 개수 불일치 등): 어느 행이 문제인지 안내하고 업로드를 취소, 기존 명단 유지.
- PIN 오입력: 오류 메시지만 표시, 편집모드 진입 안 함(잠금 횟수 제한 등은 두지 않음 — 저사양 위협 모델).

## 9. 테스트 방법

- 브라우저에서 시스템 시간을 각 구간 경계(08:59→09:00, 14:49→14:50 등)로 맞춰 아침활동 자동 닫힘, 현재 교시 강조, 방과후 라벨 전환을 눈으로 확인.
- 두 개의 브라우저 탭(하나는 "태블릿" 역할, 하나는 "폰" 역할)을 띄워 한쪽에서 편집 시 다른 쪽에 실시간 반영되는지 확인.
- 엑셀 업로드는 정상 파일 1개 + 형식이 잘못된 파일 1개로 성공/실패 케이스 확인.
- PWA 설치는 크롬(안드로이드/데스크톱)에서 설치 배너 노출 여부, iOS Safari에서 안내 문구 노출 여부 확인.
- 하이클래스 복사 버튼은 클립보드에 담긴 텍스트를 메모장 등에 붙여넣어 형식 확인.
- 타이머는 프리셋(1/3/5/10분) 클릭 시 정확한 초로 설정되는지, 직접 입력이 반영되는지, 종료 시 음성 안내와 화면 강조가 함께 뜨는지 확인.
- PC 플로팅 위젯은 데스크톱 크롬/엣지에서 버튼 클릭 시 다른 창 위에 항상 떠 있는 작은 창이 열리는지, 지원하지 않는 브라우저(파이어폭스 등)에서는 버튼이 비활성화되고 안내 문구가 뜨는지 확인.
